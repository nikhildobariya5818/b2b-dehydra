# De'Hydra B2B Platform - Setup & Deployment Guide

## Overview

Your B2B website has been transformed into a fully dynamic, database-driven platform with:
- **Admin Dashboard** for product management and client request tracking
- **Dynamic Product Pages** with brochure downloads
- **Client Contact Form** with real-time notifications
- **Google Maps Integration** for facility locations
- **Vercel Blob Storage** for brochures and images
- **Better Auth** for secure admin authentication
- **Neon PostgreSQL** database with Drizzle ORM

---

## Environment Variables Setup

All required environment variables are automatically provisioned by Neon and Blob integrations. The following are already configured:

```
DATABASE_URL                    # Neon PostgreSQL connection
DATABASE_URL_UNPOOLED          # Unpooled connection for migrations
BLOB_READ_WRITE_TOKEN          # Vercel Blob access
BETTER_AUTH_SECRET             # Session signing secret (set via v0)
GOOGLE_MAPS_API_KEY            # (Optional: Set manually for Google Maps)
BETTER_AUTH_URL                # (Optional: Set for custom domain)
```

### Setting Google Maps API Key

1. Get a Google Maps API key from [Google Cloud Console](https://console.cloud.google.com/)
2. Enable the Maps JavaScript API
3. Add to project environment variables as `GOOGLE_MAPS_API_KEY`
4. Update `app/components/google-map.tsx` if using a custom API key

## Database Setup

The database schema is automatically generated by Drizzle ORM migrations. On first deployment:

```bash
npm run build  # Generates migrations
npx drizzle-kit generate  # Creates migration files
```

### Initial Data Seeding

To populate sample products:

```bash
node -e "require('./lib/seed.ts').seed()"
```

Or manually add products through the admin dashboard.

## API Endpoints

All API endpoints are protected and scoped to the authenticated user where applicable.

### Products API
```
GET    /api/products              # List all products
GET    /api/products/[id]         # Get product by ID
POST   /api/products              # Create product (admin only)
PATCH  /api/products/[id]         # Update product (admin only)
DELETE /api/products/[id]         # Delete product (admin only)
```

### Client Requests API
```
GET    /api/client-requests       # List all requests
GET    /api/client-requests/[id]  # Get request details
POST   /api/client-requests       # Submit new inquiry
PATCH  /api/client-requests/[id]  # Update request status
```

### Facilities API
```
GET    /api/facilities            # List all facilities
POST   /api/facilities            # Add facility (admin only)
PATCH  /api/facilities/[id]       # Update facility (admin only)
DELETE /api/facilities/[id]       # Delete facility (admin only)
```

### Brochures API
```
GET    /api/brochures             # List all brochures
POST   /api/brochures             # Upload brochure (admin only)
DELETE /api/brochures/[key]       # Delete brochure (admin only)
```

## Deployment

### Deploy to Vercel

1. Connect your GitHub repository to Vercel
2. Vercel automatically detects Next.js and configures build settings
3. Environment variables are inherited from your Neon and Blob integrations
4. On deployment, migrations run automatically

```bash
git push origin main  # Triggers Vercel deployment
```

### Custom Domain Setup

1. Add your domain to Vercel project settings
2. Update `BETTER_AUTH_URL` environment variable if needed
3. Add domain to Neon Auth trusted domains:
   ```bash
   neon neon-auth domain add https://yourdomain.com
   ```

## Database Schema Overview

### Tables

**products**
- id, name, slug, category, description
- specifications (JSON), imageUrl, brochureUrl
- createdAt, updatedAt

**client_requests**
- id, contactName, companyName, email, phone
- industry, estimatedVolume, interestedProducts
- message, status (new/reviewing/responded/quoted)
- createdAt, updatedAt

**facilities**
- id, name, address, latitude, longitude
- description, type (manufacturing/warehouse/office)
- createdAt, updatedAt

**brochures**
- Stored in Vercel Blob storage (not in database)
- Metadata linked to products via brochureUrl

**Better Auth Tables**
- user, session, account, verification
- Automatically managed by Better Auth

## Performance Optimization

### Caching Strategy
- Static pages prerendered at build time: `/`, `/products`, `/about`
- Dynamic pages cached with ISR (Incremental Static Regeneration)
- API responses cached with SWR on the client side

### Image Optimization
- Next.js Image component with automatic optimization
- Lazy loading for product images
- WebP format for modern browsers

### Database Performance
- Indexed queries on frequently used columns (slug, status)
- Connection pooling via Neon
- Drizzle ORM prevents N+1 queries

## Troubleshooting

### Build Fails with DATABASE_URL Error
- Ensure Neon integration is active
- Check that DATABASE_URL is set in environment variables
- Run `npm install` to install all dependencies

### Admin Dashboard Not Accessible
- Verify BETTER_AUTH_SECRET is set in environment
- Clear browser cookies and try again
- Check browser console for auth errors

### Google Maps Not Loading
- Verify GOOGLE_MAPS_API_KEY is set
- Check API key has Maps JavaScript API enabled
- Verify domain is added to Google Cloud allowed domains

### Brochure Downloads Failing
- Verify BLOB_READ_WRITE_TOKEN is set
- Check file was uploaded successfully in admin
- Confirm file size is within Blob limits

## Development Notes

### File Structure
```
app/
  admin/              # Protected admin routes
    products/         # Product management
    requests/         # Client request management
    facilities/       # Location management
    brochures/        # Brochure management
  api/                # API endpoints
    products/
    client-requests/
    facilities/
    brochures/
    auth/[...all]/    # Better Auth handler
  locations/          # Public locations page
  products/           # Public products pages
components/
  google-map.tsx      # Google Maps component
  contact-form.tsx    # Client inquiry form
lib/
  schema.ts           # Drizzle schema
  db.ts               # Database connection
  db-operations.ts    # Drizzle queries
  auth.ts             # Better Auth config
  migrate.ts          # Migration runner
  seed.ts             # Database seeding
```

### Adding New Features

1. **Add New Product Field**: Update `lib/schema.ts`, generate migration, run migration
2. **Add Admin Page**: Create route under `app/admin/[feature]/page.tsx`
3. **Add API Endpoint**: Create route handler under `app/api/[feature]/route.ts`
4. **Add Public Page**: Create route in `app/[route]/page.tsx`
